# Reviewer demonstration
The report must be generated by the real compiled Go executable. Synthetic vectors and metadata are explicitly labeled. No fabricated terminal output, screenshots or model-generated UI images may stand in for execution.

## 30 seconds
Run `make demo`. Read the printed path and open the offline report. Compare an exact eligible result, a graph result and the plan/cardinality/work labels. The headline is approximate retrieval with explicit limits, not text generation.

## Two minutes
Inspect two tenants with overlapping IDs and very different vectors. Query the alpha scope; attempt to place `tenant` in the client request and observe rejection. Apply a narrow facet and observe exact fallback. Set budget zero and observe explicit exhaustion without a false exact guarantee.

## Five-minute engineering walkthrough
Start at Scope.Search, follow posting intersection to the planner, then follow one upper-level and bottom-level heap traversal. Compare its returned IDs with the Python exhaustive oracle. Open a deliberately weak postfilter result and explain why fewer hits are not proof there were fewer eligible records. Inspect a failed negative control and the restored test, then the source-bound receipt and remaining release gates.

## Accessibility and screenshots
HTML must use escaped text, a table caption, semantic headings, visible keyboard focus and text statuses; no script/network asset is required. Inspect at desktop and narrow widths in a real browser. Capture only after running the current source; label source hash and synthetic data. If browser access is absent, mark visual/keyboard review NOT RUN rather than generating a fake screenshot. Offline fallback is the actual JSON output plus the static report; it is not a mock of a hosted application.

## Hosted option
A sanitized static report may be published later; it cannot execute queries or establish a live-service claim. The local CLI is the authoritative demo. No giant frontend is planned.
